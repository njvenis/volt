# Closed offline lifecycle and authenticated artifact transport

Implementation contract version1, pinned before execution. This implements the
adopted offline design conditions; a cache is never an authority or upgrade path.
The paused Qualys fixture prototype does not participate in this protocol.

## Independent entry and complete authentication

The externally trusted command comes from the same independently trusted release
page as the online bootstrap. Its fixed Cosign image is
gcr.io/projectsigstore/cosign:v3.1.4@sha256:0f06154836d2de34f887a5c273506d52ca43edaa1d9e53e6510fa78a48f69c2d.
The command fixes the expected version, publisher, issuer and independent
verifier digest; downloaded cache content cannot supply those expectations.
All offline Docker executions use explicit native platform, `--pull=never`,
`--network none`, readonly rootfs, no capabilities and no-new-privileges.

Before executing the cached verifier, trusted Cosign authenticates its original
signature and SLSA provenance. Before executing any candidate shell, it verifies
the original launcher signature and exact bytes. The independent verifier then
rechecks the whole original bundle/runtime/index/both-child/config graph under
the same fixed trust policy. No prior passed bit or image presence replaces a
signature, inclusion, subject, source, platform or trusted-time check.

For OCI signatures, the fixed adapter uses `verify-attestation --local-image`
with the exact type https://sigstore.dev/cosign/sign/v1. It binds the EXACT DSSE
payload returned by that successful cryptographic verification to a single
expected subject digest and exact predicate type. Generic `verify` success and
its empty legacy critical fields are insufficient: a remaining root provenance
attestation can otherwise count as a valid signature. A matching unverified
sidefile beside a successful command is also insufficient. Runtime provenance
and verifier SLSA payloads must come from their own successful typed verification
and bind the expected original subjects and policy fields.

Production offline admission fails closed until its original, independently
provisioned public trust material, provenance, expiry and rotation boundary are
established. It never learns a root from the package or substitutes fixture
authority. The separately provisioned local verifier continues using only its
existing baked fixture key and trusted root. Fixture mechanism proof does not
establish production keyless or release qualification.

The maintained fixture first-entry command uses only the externally pinned
Cosign image and previously selected independent fixture public key/root. Before
any cached-verifier Python executes, it runs typed signature and SLSA checks
with a CUE policy generated by that trusted entry command, outside the closure:

```cue
predicateType: "https://sigstore.dev/cosign/sign/v1"
subject: [{digest: {sha256: "EXTERNALLY_EXPECTED_VERIFIER_DIGEST_HEX"}}]
```

The SLSA policy uses its exact predicate type and the same single expected
subject. Cosign evaluates these constraints against the cryptographically
verified statement inside the trusted Cosign process. The package cannot
provide a policy file or expected digest. The fixed argv suffix is
`verify-attestation --type TYPE --policy /independent-policy/NAME.cue --key
/independent-trust/fixture.pub --trusted-root /independent-trust/trusted-root.json
--local-image /closure/verifier`. All Docker flags above remain mandatory.
Original launcher and bundle `verify-blob` checks follow, then a first-entry
component may execute only the now-authenticated verifier's `--help`. This
component does not qualify the offline full graph or lifecycle. Production has
no fixture selection flag. Policy semantics are checked against the pinned
[Cosign3.1.4 implementation](https://github.com/sigstore/cosign/blob/v3.1.4/pkg/policy/attestation.go).

## Artifact closure format

The fixed readonly verifier mount is `/run/volt-offline-artifacts`. Its
`closure.json` is canonical sorted compact ASCII JSON plus one newline, with
duplicate rejection. Exact top-level keys are `schema_version` (integer1),
`profile` (volt_offline_artifacts_v1), `release`, and `files`.

The exact release keys are `version`, `signer`, `issuer`, `verifier_reference`,
`runtime_reference`, `source_revision`, `source_snapshot`, `bundle_sha256`, and
`launcher_sha256`. Digests are sha256 plus64 lowercase hex. Source revision is
40 lowercase hex. These declarations are checked against externally expected
policy and verified signed payloads; they are not trust inputs.

`files` maps normalized relative names to exactly `bytes` (nonnegative integer,
not boolean) and `sha256`. The inventory excludes closure.json itself to avoid
a digest cycle. It contains exactly the original four package members under
`package/` (launcher.sh, launcher.sigstore.json, installer.bundle.tar.gz,
installer.bundle.sigstore.json), plus OCI authentication layouts at the fixed
names `runtime-index`, `runtime-amd64`, `runtime-arm64`, and `verifier`.
Each layout permits only index.json, oci-layout, and blobs/sha256/64hex.
There are no arbitrary paths, links, special files, hardlinks, extra root files,
alternative keys, policies, profiles or commands. Limits: 4096 files, 128MiB
total, 64MiB installer bundle, 1MiB other members, 1MiB closure.json.

Keep exact original index, BOTH native manifests/configs, descriptors and all
signature/provenance referrer manifests, Sigstore DSSE bundles, inclusion
proof/checkpoint/SET, certificate/SCT/trusted-time data. OCI filesystem-layer
bytes are excluded from this authentication transport; their original signed
descriptors remain intact. The separately cached engine image must still match
the exact selected config/child witness before execution. No implicit pull is
permitted. This avoids fetching the other architecture's filesystem archive
merely to authenticate its manifest/config and signature.

Metadata export accepts only the fixed official repositories, or the separately
baked local-fixture repositories. It fetches bounded raw index/manifests/configs
and standard OCI referrers. Registry2.8's standard referrer fallback tag is
sha256-DIGESTHEX; the native referrers endpoint may return404, after which only
that exact derived tag is tried. This is transport discovery, never alternate
trust. Every content-addressed object is hash/size/media/subject checked; no
filesystem-layer payload is fetched. Unknown graph objects or missing proofs
fail closed. No source rewrite, signing, key generation or publication occurs.
Derive omissions from the reachable typed graph; preserve every authentication
or proof blob, including shared references. A fetch failure is never an omission.
The fixed --export-offline-artifacts verifier action first completes normal
online graph admission, then writes only a fresh empty host-owned0700 staging
mount at /run/volt-offline-artifacts, and reruns full offline verification before
returning the receipt. It does not publish an installed cache or write a journal.
Stage files are new0600 regular files written through no-follow directory FDs,
with unchanged root inode, bounded inventory and file/directory fsync. Each
layout preserves its original raw root/descendant manifests, configs, referrer
discovery index, attachments and proof blobs; index.json/oci-layout are the fixed
Cosign transport wrapper. Only declared supported executable-image filesystem
layer payloads may be absent. Unknown types, missing mandatory objects and
another attachment subject deny. A digest shared by filesystem and mandatory
proof/config edges is retained; the mandatory edge always wins. Graph role is
established before traversal: referrers, artifact/subject-bearing
manifests and non-native index children are proof roles regardless of config.
Only independently expected native executable roles may omit filesystem edges;
native-looking proof configs never confer that permission. Proof-role filesystem
media is mandatory bounded data, not an omission; excessive/unsupported data
denies. The current exporter selects ONLY the owned loopback fixture repositories from baked policy;
production export fails closed before writing until independent original public
trust/time provisioning is adopted. Package data cannot select this policy.

Readers use bounded NONBLOCK/NOFOLLOW regular single-link descriptor reads,
current host UID, exact private mode0600 and stable pre/post-read identity.
Directories are current-host-owned0700 and walked without following links.
The journal pins the exact closure inventory and launcher hash/result after
successful initial admission. That detects substitution; every offline call
still reruns cryptographic authentication. No cache backfill, root rotation,
adoption or image upgrade is inferred from missing fields.

The independent verifier's fixed --offline-artifacts adapter uses that SAME
mount; --expected-verifier-reference is the external bootstrap's exact pin,
not a policy or root selector. Its baked policy alone selects production or
the independently provisioned fixture verification material. Bundle-only
discovery reauthenticates verifier signature/SLSA and original launcher/bundle
blobs, requires exact original bytes and the same launcher inside the signed
closed bundle, and returns only the signed runtime reference/bundle hash.
Full admission additionally reauthenticates signatures for the exact raw index
and BOTH child roots, obtains the original successful typed runtime-provenance
DSSE envelope without re-encoding, and applies the existing source/version/
bundle/platform/manifest/config/selected-object policy to cached graph bytes
and a fresh actual engine inspection. Unknown selected IDs, an index-only
witness, missing configs, wrong subjects and changed source all deny. No
registry fetch or fallback occurs inside this adapter. Original cache identity
is rechecked throughout. The returned offline_artifacts receipt has exactly
schema_version integer1, profile volt_verified_installer_v1, closure_sha256,
launcher_sha256, bundle_sha256, verifier_reference, signer and issuer. These
fresh results are compared with the selected journal under the actual FD;
they never replace cryptographic verification or grant recreation authority.

## Dedicated installed verification anchor and initial pin

The canonical selected STATE determines exactly STATE.installer-artifacts/,
an owned0700 dedicated sibling containing verification material ONLY. It never
contains an instance directory, signing/encryption seed, account state, another
instance or operator authority. The committed closure is its fixed originals/
child. Before publication, the one exact durable journal stage has the basename
.originals.partial.XXXXXXXX (eight ASCII alphanumeric characters). No caller
selects another cache parent, child path, policy or key. Both children are
owned0700; original files retain owned single-link0600/no-follow custody.

Allowed anchor states are exactly the one recorded stage before publication,
exact originals after publication, or those two exact children during a
no-replace collision with byte-identical freshly authenticated material. Unknown,
duplicate, linked, foreign, differently permissioned or contradictory children
deny. Initial identity/key creation requires STAGE ONLY: an existing originals
directory cannot authorize a new installation. AFTER a durable pin exists,
loss of the stage name following rename is legitimate only when the live exact
originals inode, bytes, fresh crypto result, image/source and journal pin agree.
No different stage is adopted or reconstructed to make an operation succeed.

The fixed /run/volt-cache-parent ROI maps ONLY this dedicated anchor. Initial
and lifecycle helpers receive it read-only; the independently authenticated
fixed cache publisher uses write access for anchored renameat2 no-replace and
parent fsync. STATE.parent and other instances/keys are never mapped for this
purpose. /run/volt-offline-artifacts maps only the exact stage/originals child.
Actual API mount/volume source and ancestor exclusion protects the ENTIRE anchor.

Same-invocation fresh independent pre-lock verification binds the exact closed
initial request SHA256. The actual initial FD owner, BEFORE any identity/key
creation, rereads the receipt and all original cache bytes, compares every
release/policy/bundle/image expectation, and uses its live anchor FD to require
the ORIGINAL NAMED stage inode equals its fixed closure bind. A still-readable
bind view after disappearance/replacement of that name is insufficient. The
anchor entry is fsynced before keys; private stage data and directory entries
were already fsynced by export. There is no pre-init challenge or passed-bit
authority. Initial verification failure creates no identity/secret state.

The one initial metadata commit includes installer_contract_version integer2,
the closed eight-field installer_admission pin, installer_cache_stage,
installer_initial_request_sha256, installer_phase prepared, and
installer_initial_files. The latter is a bounded (1..128) relative-path map to
exact sha256, integer mode and integer bytes (at most1MiB each), preserving all
committed initial key/config files. Before prepared-phase custody work, validate
these original fingerprints under the actual held FD; missing/changed secrets
or configuration fail, never regenerate. Full ordinary instance/custody/fence
validation remains mandatory before workers or ingress.
The mutable .env slot reuses ONLY the existing durable env_sha256 and
local_start_environment_pending_sha256 transition owned by prepare_start.
After its legitimate replacement, accept exactly the committed current or
pending bytes with original private custody; never refresh immutable initial
fingerprints from observed environment bytes and never introduce another env
authority. Arbitrary changes and missing/changed keys still deny before writes.

The source stage remains OUTSIDE ephemeral WORK cleanup until publication.
Pin/key commit followed by an interruption may leave that exact private stage
and durable intent. Resume only that recorded stage after fresh authentication,
current FD, pin, source and key-fingerprint checks; never create a replacement
stage, fill a missing established pin or infer completion by filename. If rename
already committed, accept only exact authenticated originals as above. Explicit
instance data destruction retains this verification-only anchor for recovery;
its retention grants no identity/account/key/setup recreation authority.

## Same-owner lifecycle exchange

Only three fixed lock-owner actions exist: backup-record, restore-provision,
restore-admit. No request selects code, command, module, path or operation.
The admitted process opens the existing lifecycle inode NONBLOCK/NOFOLLOW,
validates current-host UID, regular single-link0600/size0/stable identity and
actually acquires exclusive flock before reading inputs or mutating anything.
Contention exits75. The SAME FD remains held through all journal/fence changes,
three store archives, the instance archive, final capture acknowledgement and
atomic publication. An unrelated held lock or owner token is never authority.

Fixed mounts: `/state`, RO `/package`, RO `/run/volt-offline-input`, RW
`/run/volt-offline-output`, and for capture only the selected private backup
parent at `/run/volt-backup-publication`. Exchange directories are fresh0700;
all records are0600. No API mount includes any of these directories, the
operator keys or their ancestor. No helper receives a Docker socket/config/API.
The fixed restore-provision holder alone starts with root effective UID and
CHOWN, SETUID and DAC_OVERRIDE, matching the existing fence writer. Its real UID
is the validated selected host owner. It retains the same acquired FD while
calling the existing restore writer; generic readers and other holders do not
receive these capabilities. Fence mode/ownership is set before publication.

The initial fixed input is request.json with exactly integer schema_version1,
profile volt_offline_request_v1, setup_sha256, and backup_name. The latter is a
bounded new basename for backup and null for either restore action. The emitter
has only readonly package/data mounts and creates no instance identity or secret.
The process action is fixed by its own lock-holder flag, never request data.
It loads only fixed readonly /package/setup.py after checking its admitted hash.

Every exchange record has exactly `schema_version`, `profile`, `operation`,
`operation_id`, `identity`, `phase`, `predecessor_sha256`, and `data`.
Schema version is integer1, profile volt_offline_lifecycle_v1. Operation equals
the fixed process action. Operation ID is a new canonical UUIDv4. Identity has
exactly installation_id, journal_id, image_reference, image_id, image_id_kind,
source_revision, source_snapshot, platform, restore_generation, recovery_epoch_id.
It comes from the validated journal under lock. Generation is a nonnegative
integer, epoch null only for generation0; image kind is config or
selected_manifest. Correlation is never authority. Each response/input matches
the fresh operation UUID, exact identity and previous canonical record hash.
Unknown, stale, conflicting retry or cross-operation phases fail closed.
The first response has null predecessor; every later input/output has the exact
sha256 of the previous canonical record. The operation UUID is generated by the
actual owner, not supplied in the initial request. Consumed inputs and the held
inode are checked for identity changes throughout the operation.

Fixed owner outputs are plan.json then capture.json (backup), provision.json
(provision), and complete.json. Host inputs are observed.json, captured.json or
provisioned.json as appropriate. The data-only emitter reads only fixed readonly
Docker-observation files; it cannot invoke a writer or claim a lock. Observations
have exactly image, containers, volumes, networks, logs, logs_since, inventories.
Only projected Docker fields needed for current source/image, resource, mount,
ownership and cold-stop validation survive. Shutdown evidence acquisition uses
the actual saved container State.StartedAt as the exact Docker query value:
`docker logs --tail 256 --since STARTED_AT PROJECT-volt-1`. A private FIFO joins
that producer to the fixed data-only filter; no lifetime log file is buffered.
The filter reads at most65536 bytes at a time (including arbitrarily long lines),
retains only the five fixed shutdown markers/error indicator and byte count,
and has a120-second acquisition deadline. The caller waits for and checks BOTH
the actual Docker producer and filter exit. Either failure denies observation.
The canonical private shutdown-evidence.json has exactly schema_version1,
profile volt_controlled_stop_evidence_v1, queried_started_at, markers,
stop_error and bytes_seen. Its queried timestamp must equal the observed
container's StartedAt; all five markers and stop_error false are mandatory.
The exchange contains only these fixed markers, never raw log text.
Inventories have exactly sha256 (64hex), nonnegative integer entries, and nullable
postgres_version. Store keys are exactly postgres/media/state, adding instance
only for final capture. Ordinary application-network Internal remains false;
the separately paused F topology contract does not select it here.

Fixed phase files are newly created per operation, never reused across calls.
The holder emits the initial validated plan only after actual lock acquisition;
the host gathers fixed Docker inspections and RO inventories and returns data.
The holder rechecks journal/resource identities before each mutation. Inputs
cannot declare completion by filename or select/rewrite an expected identity.

Backup: require current successful controlled stop and current shutdown markers;
verify all three existing inventories before committing backup_inventory. Capture
all three stores and instance under the same FD into an owner-private partial
directory. Reinspect resources and compare inventories after capture. Verify and
fsync the four exact regular archive files. Only the still-lock-owning process
may atomically rename to a new completed destination and fsync its parent. Owner
loss or uncertainty BEFORE publication leaves only private partials. The atomic
no-replace rename is the capture commit point: owner or response loss AFTER it
can leave a valid completed-but-unacknowledged capture. Preserve that published
directory; never delete, replace, promote a partial, or infer host receipt from
a filename. Preserve numeric ownership and all cryptographic/auth state.
Capture helpers expose only fixed inventory/capture actions and four fixed store
names, with readonly /restore and private /backup. Root capture uses only
DAC_OVERRIDE and CHOWN, writes a new O_EXCL/NOFOLLOW0600 archive via stdout, then
sets host ownership after mode, fsyncs and closes it. The owner independently
parses each numeric-owner tar and compares file types/modes/UIDs/GIDs/content
hashes with the final readonly source inventory before publication. Hardlinks,
special files, duplicate/traversing paths, escaping links and symbolic-link
parents fail. Current bounds are250000 entries,64GiB per archive/store and32GiB
per member; extended tar metadata is bounded before allocation. All final
archive identities/digests remain stable while acknowledged. Publication uses
Linux renameat2 RENAME_NOREPLACE plus parent fsync while the actual FD is held;
unsupported atomic publication fails closed, with private partials preserved.

The completion receipt is the canonical closed lifecycle complete record,
with data exactly backup_name and archives (the four names, each bytes/sha256).
The initial owner plan prints its fresh operation_id and canonical identity
SHA256 before capture. These are correlation values, never execution authority.
Read-only reconciliation is the fixed public command `backup-status`, requiring
--directory, --backup-directory, --operation-id and --identity-sha256. It mounts
only that selected instance and published backup read-only into the already
admitted native image, with network none, pull never and all capabilities
dropped. It accepts only a non-partial basename, the exact closed receipt,
original UUIDv4/identity hash/name, same immutable installation/journal/image/
source identity, valid captured restore tuple, and four private single-link
0600 archive files whose sizes/digests remain stable. Selected metadata and
receipt must remain unchanged throughout readback. The result reports
status completed_capture, read_only_reconciliation true,
host_response_acknowledgement not_inferred, restore_authority false, exact
correlation/completion digest and archive inventory. It performs no journal,
fence, acknowledgement, restore or completion mutation. Another operation,
changed archive, incomplete directory or contradictory identity fails closed.
A retry of backup-record against an existing destination denies before journal
mutation; reconciliation never overwrites the committed capture.

Restore provision: persist the existing pending from/to intent BEFORE changing
fence/start projection or creating resources. Reuse current forward-only
reconciliation, fingerprints and generation/epoch. Emit only the journal-derived
fixed resource plan for host Docker CLI execution; verify exact post-create
inspection before completion. Restart resumes only the durable same intent and
epoch. No runtime container, initial true grant or claim/authority recreation.

Restore admit: require pending import and no runtime container. Compare all three
actual RO store inventories with the captured backup_inventory. Empty/corrupt
or contradictory imports fail before candidate startup. Commit restore_imported
only on equality. Existing protected maintenance then revokes sessions and
capabilities, obtains the exact tuple acknowledgement and disarms before ingress.

## Qualification boundary

The maintained runner must use signed launcher commands under restricted PATH
for every lifecycle phase; browser tooling is a separately recorded controller
dependency. Test owner concurrency/loss, stale/cross-operation exchanges,
partial-capture publication denial, crash-forward restore, foreign resources,
empty/corrupt imports, platform/mount/private-file contradictions and exact ack.
Exercise owned-registry outage with complete cache and cached images, plus each
missing/tampered original artifact class, before claiming offline support.
All new source is archived before runs; raw failed attempts remain unchanged.

## Stable resource comparison and retained diagnostics

Only semantically unordered sets are canonicalized: containers by Id, volumes
by Name, networks by Name, and mounts by Destination. Keys must be unique
strings. Every row value remains present; duplicates and contradictions fail.
Authority fields, descriptors and all other array ordering remain unchanged.
Validated before/after resource projections are retained in owner logs with
every leaf replaced by its type and SHA256, so differing identity fields can
be assessed without disclosing secret values. Exact phase-record digests and
operation UUIDs accompany these traces. The host retains owner logs on both
success and failure. No completed backup is published on a mismatch.

## External offline entry and pre-extraction admission

The maintained fixture controller provisions a separate owned0700 POSIX entry
from its independently selected ORIGINAL admission: fixed Cosign digest,
verifier/runtime references, native platform, source revision/snapshot, RC4
version and original public key/trusted root. Neither journal nor downloaded
cache chooses these expectations. Production trust/time activation stays closed.
The entry authenticates exact verifier signature/SLSA subjects with trusted
Cosign CUE before any verifier execution, and original launcher/bundle blobs
before shell execution. Every Docker execution is network-none/pull-never.
It then runs full original graph admission against a fresh cached-engine inspect.

The single fixed `verify-cache --directory CANONICAL_STATE` action performs this
same complete external authentication and exits without any candidate launcher,
helper, extraction, identity writer or journal reconstruction. This is the
required admission BEFORE instance extraction. Subsequent restore provisioning
repeats authentication and compares the RESTORED exact pin before authority or
workers. Missing pins never trigger backfill. All extraction/import containers
also require explicit pull-never.

If committed originals is absent, entry/launcher may discover only a single
nonlinked directory with the fixed .originals.partial. plus eight ASCII alnum
name under the dedicated anchor. This selects a TRANSPORT VIEW only, creates
nothing, and grants no authority. Fresh independent verification must compare
its exact original bytes, live inode, journal-bound stage, prepared/unestablished/
unacknowledged generation-zero intent and immutable fingerprints before an
actual FD owner can continue publication. Unknown, multiple, substituted,
acked/established or restored-stage contradictions deny. Offline NEW install
remains denied; verification-only material never recreates an instance.
