# Closed offline lifecycle and authenticated artifact transport

Implementation contract version1, pinned before execution. This implements the
adopted offline design conditions; a cache is never an authority or upgrade path.
The paused Qualys fixture prototype does not participate in this protocol.

## Independent entry and complete authentication

The externally trusted command comes from the same independently trusted release
page as the online bootstrap. Its fixed Cosign image is
gcr.io/projectsigstore/cosign:v3.1.4@sha256:0f06154836d2de34f887a5c273506d52ca43edaa1d9e53e6510fa78a48f69c2d.
The command fixes the expected version, publisher, issuer and independent
verifier digest; downloaded cache content cannot supply those expectations.
All offline Docker executions use explicit native platform, `--pull=never`,
`--network none`, readonly rootfs, no capabilities and no-new-privileges.

Before executing the cached verifier, trusted Cosign authenticates its original
signature and SLSA provenance. Before executing any candidate shell, it verifies
the original launcher signature and exact bytes. The independent verifier then
rechecks the whole original bundle/runtime/index/both-child/config graph under
the same fixed trust policy. No prior passed bit or image presence replaces a
signature, inclusion, subject, source, platform or trusted-time check.

For OCI signatures, the fixed adapter uses `verify-attestation --local-image`
with the exact type https://sigstore.dev/cosign/sign/v1. It binds the EXACT DSSE
payload returned by that successful cryptographic verification to a single
expected subject digest and exact predicate type. Generic `verify` success and
its empty legacy critical fields are insufficient: a remaining root provenance
attestation can otherwise count as a valid signature. A matching unverified
sidefile beside a successful command is also insufficient. Runtime provenance
and verifier SLSA payloads must come from their own successful typed verification
and bind the expected original subjects and policy fields.

Production offline admission fails closed until its original, independently
provisioned public trust material, provenance, expiry and rotation boundary are
established. It never learns a root from the package or substitutes fixture
authority. The separately provisioned local verifier continues using only its
existing baked fixture key and trusted root. Fixture mechanism proof does not
establish production keyless or release qualification.

The maintained fixture first-entry command uses only the externally pinned
Cosign image and previously selected independent fixture public key/root. Before
any cached-verifier Python executes, it runs typed signature and SLSA checks
with a CUE policy generated by that trusted entry command, outside the closure:

```cue
predicateType: "https://sigstore.dev/cosign/sign/v1"
subject: [{digest: {sha256: "EXTERNALLY_EXPECTED_VERIFIER_DIGEST_HEX"}}]
```

The SLSA policy uses its exact predicate type and the same single expected
subject. Cosign evaluates these constraints against the cryptographically
verified statement inside the trusted Cosign process. The package cannot
provide a policy file or expected digest. The fixed argv suffix is
`verify-attestation --type TYPE --policy /independent-policy/NAME.cue --key
/independent-trust/fixture.pub --trusted-root /independent-trust/trusted-root.json
--local-image /closure/verifier`. All Docker flags above remain mandatory.
Original launcher and bundle `verify-blob` checks follow, then a first-entry
component may execute only the now-authenticated verifier's `--help`. This
component does not qualify the offline full graph or lifecycle. Production has
no fixture selection flag. Policy semantics are checked against the pinned
[Cosign3.1.4 implementation](https://github.com/sigstore/cosign/blob/v3.1.4/pkg/policy/attestation.go).

## Artifact closure format

The fixed readonly verifier mount is `/run/volt-offline-artifacts`. Its
`closure.json` is canonical sorted compact ASCII JSON plus one newline, with
duplicate rejection. Exact top-level keys are `schema_version` (integer1),
`profile` (volt_offline_artifacts_v1), `release`, and `files`.

The exact release keys are `version`, `signer`, `issuer`, `verifier_reference`,
`runtime_reference`, `source_revision`, `source_snapshot`, `bundle_sha256`, and
`launcher_sha256`. Digests are sha256 plus64 lowercase hex. Source revision is
40 lowercase hex. These declarations are checked against externally expected
policy and verified signed payloads; they are not trust inputs.

`files` maps normalized relative names to exactly `bytes` (nonnegative integer,
not boolean) and `sha256`. The inventory excludes closure.json itself to avoid
a digest cycle. It contains exactly the original four package members under
`package/` (launcher.sh, launcher.sigstore.json, installer.bundle.tar.gz,
installer.bundle.sigstore.json), plus OCI authentication layouts at the fixed
names `runtime-index`, `runtime-amd64`, `runtime-arm64`, and `verifier`.
Each layout permits only index.json, oci-layout, and blobs/sha256/64hex.
There are no arbitrary paths, links, special files, hardlinks, extra root files,
alternative keys, policies, profiles or commands. Limits: 4096 files, 128MiB
total, 64MiB installer bundle, 1MiB other members, 1MiB closure.json.

Keep exact original index, BOTH native manifests/configs, descriptors and all
signature/provenance referrer manifests, Sigstore DSSE bundles, inclusion
proof/checkpoint/SET, certificate/SCT/trusted-time data. OCI filesystem-layer
bytes are excluded from this authentication transport; their original signed
descriptors remain intact. The separately cached engine image must still match
the exact selected config/child witness before execution. No implicit pull is
permitted. This avoids fetching the other architecture's filesystem archive
merely to authenticate its manifest/config and signature.

Metadata export accepts only the fixed official repositories, or the separately
baked local-fixture repositories. It fetches bounded raw index/manifests/configs
and standard OCI referrers. Registry2.8's standard referrer fallback tag is
sha256-DIGESTHEX; the native referrers endpoint may return404, after which only
that exact derived tag is tried. This is transport discovery, never alternate
trust. Every content-addressed object is hash/size/media/subject checked; no
filesystem-layer payload is fetched. Unknown graph objects or missing proofs
fail closed. No source rewrite, signing, key generation or publication occurs.
Derive omissions from the reachable typed graph; preserve every authentication
or proof blob, including shared references. A fetch failure is never an omission.
The fixed --export-offline-artifacts verifier action first completes normal
online graph admission, then writes only a fresh empty host-owned0700 staging
mount at /run/volt-offline-artifacts, and reruns full offline verification before
returning the receipt. It does not publish an installed cache or write a journal.
Stage files are new0600 regular files written through no-follow directory FDs,
with unchanged root inode, bounded inventory and file/directory fsync. Each
layout preserves its original raw root/descendant manifests, configs, referrer
discovery index, attachments and proof blobs; index.json/oci-layout are the fixed
Cosign transport wrapper. Only declared supported executable-image filesystem
layer payloads may be absent. Unknown types, missing mandatory objects and
another attachment subject deny. A digest shared by filesystem and mandatory
proof/config edges is retained; the mandatory edge always wins. Graph role is
established before traversal: referrers, artifact/subject-bearing
manifests and non-native index children are proof roles regardless of config.
Only independently expected native executable roles may omit filesystem edges;
native-looking proof configs never confer that permission. Proof-role filesystem
media is mandatory bounded data, not an omission; excessive/unsupported data
denies. The current exporter selects ONLY the owned loopback fixture repositories from baked policy;
production export fails closed before writing until independent original public
trust/time provisioning is adopted. Package data cannot select this policy.

Readers use bounded NONBLOCK/NOFOLLOW regular single-link descriptor reads,
current host UID, exact private mode0600 and stable pre/post-read identity.
Directories are current-host-owned0700 and walked without following links.
The journal pins the exact closure inventory and launcher hash/result after
successful initial admission. That detects substitution; every offline call
still reruns cryptographic authentication. No cache backfill, root rotation,
adoption or image upgrade is inferred from missing fields.

The independent verifier's fixed --offline-artifacts adapter uses that SAME
mount; --expected-verifier-reference is the external bootstrap's exact pin,
not a policy or root selector. Its baked policy alone selects production or
the independently provisioned fixture verification material. Bundle-only
discovery reauthenticates verifier signature/SLSA and original launcher/bundle
blobs, requires exact original bytes and the same launcher inside the signed
closed bundle, and returns only the signed runtime reference/bundle hash.
Full admission additionally reauthenticates signatures for the exact raw index
and BOTH child roots, obtains the original successful typed runtime-provenance
DSSE envelope without re-encoding, and applies the existing source/version/
bundle/platform/manifest/config/selected-object policy to cached graph bytes
and a fresh actual engine inspection. Unknown selected IDs, an index-only
witness, missing configs, wrong subjects and changed source all deny. No
registry fetch or fallback occurs inside this adapter. Original cache identity
is rechecked throughout. The returned offline_artifacts receipt has exactly
schema_version integer1, profile volt_verified_installer_v1, closure_sha256,
launcher_sha256, bundle_sha256, verifier_reference, signer and issuer. These
fresh results are compared with the selected journal under the actual FD;
they never replace cryptographic verification or grant recreation authority.
