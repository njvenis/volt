# G7 upgrade rollback development delta

Status: implementation delta for FR-OP-01, G7-REC-01, G7-PKG-01 and CR-01/03/09/10/11. It implements only a local disposable 0058 to 0059 upgrade rollback proof. It selects no production policy, release, visibility, retention, RPO or RTO decision.

## Compatibility contract

- Image A is the executable source snapshot at `983ce03455de33fa48f34d6a656d700873b37319`, with the captured startup guard/invocation overlay and runtime package-manifest copies retained separately. It is a development fixture with known NO-GOs. Image B is the complete candidate from the authorized implementation branch. Both image identities bind a canonical package manifest digest and complete source snapshot digest.
- Before any service role change, CE initialization, migration, listener or worker startup against an existing cluster, the image-owned guard reads the exact Alembic heads and compares them with that image's supported schema set and startup mode. It rejects unknown, multiple, or mode-incompatible heads without modifying the database. Empty database bootstrap remains a separate path. A rejects schema 0059.
- B's ordinary mode requires 0059. Its explicitly fenced upgrade-verification mode may inspect 0058, but may proceed to the one-shot 0058 to 0059 migration only after the host journal binds the source and target image/package identities, verified archive digest, exact transition, and replacement volume IDs. Automatic migrations stay disabled. No downgrade occurs.
- Archive restoration uses the exact source image/package bound in the archive. Upgrade verification uses B on restored copies in fresh volumes. Rollback uses the original archive, A and a second fresh volume set, and advances the external epoch floor. Neither attempt mounts a volume used by another image.

## Effect boundary

The source cold-capture, recovery-control, supported API readback, queue reconciliation and release machinery stays authoritative. B remains fenced for product writes and external effects throughout its lifetime. The only database changes admitted after the archive are the exact 0058 to 0059 Alembic head/table delta and enumerated control deltas in the G7 backup settings/state/host/quarantine/projection tables, append-only authentication and host-report audit rows, and the single synthetic deployment/provider status and OIDC sync records. Existing rows in append-only tables must remain byte-identical by payload digest; mutable status rows may change only at their exact synthetic deployment/provider keys. The runner records complete per-table schema and row-payload hashes for both UVM and DefectDojo, plus every CE media-file digest; it rejects same-count product payload changes, any non-allowlisted or semantically invalid table delta, and any media change. The measured delta enumeration and source/candidate inventory digests bind to the external controller journal and rollback request with archive, image, package, epoch and forward-volume identities. The queue validator requires a known empty Valkey DB0, no queued tasks or unresolved intent, and explicit absent-worker classification supported by missing runtime PIDs; unexplained or failed reads reject rollback. Any mismatch, missing evidence, stale/replayed context or unresolved acknowledged effect blocks rollback and preserves B's forward volumes. A successful rollback requires the measured product mutation count, unexpected delta count and unresolved effect count to be zero; control mutation count is retained as measured.

## Decisive executable journey

`tools/g7_container_journey.sh --upgrade-rollback-only` extends the maintained backup/recovery runner. It builds and binds A and B, establishes supported-API before-capture sentinels, performs a coordinated stopped three-volume archive, restores A's state into fresh forward volumes under epoch 1, proves schema 0058 and retained readback, executes the explicit fenced Alembic upgrade to 0059, proves post-migration readback, and records the rollback request while preserving the effect fence. It validates complete inventory deltas and queue state, restores the original archive into separate fresh rollback volumes with A under epoch 2 and a new connector recovery UUID, reconciles held queues, and signs verification over the epoch-2 A UVM, CE and media readbacks plus exact image/package/archive/volume/connector context. It rejects stale epoch-1 context and proves admitted worker/scheduler progress after removing the container network namespace's default route. The connected local-control route remains available, and a bounded TEST-NET probe records `ENETUNREACH` from the released runtime.

Negative assertions cover A on 0059; unknown/multiple heads; unsupported compatibility; same-count payload edits; unrelated table changes; unknown queue tasks, broker contents or failed reads; missing/mismatched epoch-2 readbacks; missing/corrupt archive evidence; mismatched image/package binding; stale epoch/replay; and failed release. The supported Gitless A reconstruction consumes the retained source tar, overlay, compatibility module, schema declaration and recorded source epoch, restores deterministic source/overlay permissions and asserts the executed context digest without requiring Git history. Measurements are descriptive and environment-labelled, including separate upgrade, rollback and outage durations. The runner retains the exact source snapshot, overlay, image/package identities, invocation, raw exits/output, archive/readback evidence, and per-volume cleanup/absence results. No private historical evidence or runtime credential enters the public tree or retained evidence.
