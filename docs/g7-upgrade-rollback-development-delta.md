# G7 upgrade rollback development delta

Status: implementation delta for FR-OP-01, G7-REC-01, G7-PKG-01 and CR-01/03/09/10/11. It implements only a local disposable 0058 to 0059 upgrade rollback proof. It selects no production policy, release, visibility, retention, RPO or RTO decision.

## Compatibility contract

- Image A is the executable source snapshot at `983ce03455de33fa48f34d6a656d700873b37319`, with the captured startup guard/invocation overlay and runtime package-manifest copies retained separately. It is a development fixture with known NO-GOs. Image B is the complete candidate from the authorized implementation branch. Both image identities bind a canonical package manifest digest and complete source snapshot digest.
- Before any service role change, CE initialization, migration, listener or worker startup against an existing cluster, the image-owned guard reads the exact Alembic heads and compares them with that image's supported schema set and startup mode. It rejects unknown, multiple, or mode-incompatible heads without modifying the database. Empty database bootstrap remains a separate path. A rejects schema 0059.
- B's ordinary mode requires 0059. Its explicitly fenced upgrade-verification mode may inspect 0058, but may proceed to the one-shot 0058 to 0059 migration only after the host journal binds the source and target image/package identities, verified archive digest, exact transition, and replacement volume IDs. Automatic migrations stay disabled. No downgrade occurs.
- Archive restoration uses the exact source image/package bound in the archive. Upgrade verification uses B on restored copies in fresh volumes. Rollback uses the original archive, A and a second fresh volume set, and advances the external epoch floor. Neither attempt mounts a volume used by another image.

## Effect boundary

The source cold-capture, recovery-control, supported API readback, queue reconciliation and release machinery stays authoritative. B remains fenced for product writes and external effects throughout its lifetime. The baseline is captured after the supervisor acknowledges that source producers and admission listeners stopped. Complete UVM and CE row-payload, column/default/constraint/index inventories and CE media digests must match an independently derived expectation. Offline replay of exact externally journaled recovery submissions, using their retained acknowledgement clocks and real control handlers, derives the expected backup-state fields, immutable host records and exact quarantine rows. The only schema allowance is the reviewed 0058 to 0059 head change and empty projection-evidence table. Desired configuration revisions, authentication/OIDC state, observer status and all other product rows must remain unchanged. There are no table or deployment-key exclusions. Replay fails if a submission or acknowledgement is missing, inconsistent or outside the admitted control operations. Its expectation digest and exact admitted deltas are retained in the external controller journal with archive, image, package, epoch and forward-volume bindings.

Queue classification requires the raw Celery EX_UNAVAILABLE exit 69 and exact no-node diagnostic, a separately measured absence of worker/scheduler processes and PID files, a healthy empty Valkey DB0, unchanged durable intent inventory and no unexplained unresolved state. Exit 137, a read exception or an unknown diagnostic cannot become a successful absence observation. The rollback request requires zero product mutations, unexpected changes and unresolved effects, and exact agreement with its bound attestation. Every mismatch preserves B volumes for reconciliation.

## Decisive executable journey

`tools/g7_container_journey.sh --upgrade-rollback-only` extends the maintained backup/recovery runner. It builds and binds A and B, establishes supported-API before-capture sentinels, performs a coordinated stopped three-volume archive, restores A's state into fresh forward volumes under epoch 1, proves schema 0058 and retained readback, executes the explicit fenced Alembic upgrade to 0059, proves post-migration readback, and records the rollback request while preserving the effect fence. It validates complete inventory deltas and queue state, restores the original archive into separate fresh rollback volumes with A under epoch 2 and a new connector recovery UUID, reconciles held queues, and signs verification over the epoch-2 A UVM, CE and media readbacks plus exact image/package/archive/volume/connector context. It rejects stale epoch-1 context and proves admitted worker/scheduler progress under the namespace fence installed before the entrypoint on every recovery startup and restart. Both recovery modes use the same fenced launch wrapper. The connected local-control route remains available, and a bounded TEST-NET probe records `ENETUNREACH` from the released runtime.

Negative assertions cover A on 0059; unknown/multiple heads; unsupported compatibility; same-count payload edits; unrelated table changes; unknown queue tasks, broker contents or failed reads; missing/mismatched epoch-2 readbacks; missing/corrupt archive evidence; mismatched image/package binding; stale epoch/replay; and failed release. The supported Gitless A reconstruction consumes the retained source tar, overlay, compatibility module, schema declaration and recorded source epoch, restores deterministic source/overlay permissions and asserts the executed context digest without requiring Git history. Measurements are descriptive and environment-labelled, including separate upgrade, rollback and outage durations. The runner retains the exact source snapshot, overlay, image/package identities, invocation, raw exits/output, archive/readback evidence, and per-volume cleanup/absence results. No private historical evidence or runtime credential enters the public tree or retained evidence.

## Preflight before structural implementation

- The historical implementation preflight used a clean checkout with Docker client/server 29.6.2. Pinned VOLT/CE images and Playwright browser binaries were available in that environment. Host Python dependency availability was incomplete, so the pinned host compile/import check was not established there; use an authorized pinned runtime before claiming it.
- Docker Desktop routes bridge traffic through its VM, so a host nftables forward chain did not observe the container probe. The maintained runner therefore applies the egress fence inside the admitted container network namespace by removing its default route while preserving the connected host-control route. A disposable preflight proved loopback-published host control remained reachable and the TEST-NET connection returned `101` (`ENETUNREACH`). The full journey must retain the same runtime proof before this contract is considered exercised.
- The daemon rejected publishing `127.0.0.1:9000` with `/forwards/expose` HTTP 500 despite an unbound host port. A short-lived disposable mapping to `127.0.0.1:18000` succeeded. The maintained fixture publishes its internal OIDC listener on a preflight-selected loopback port and proxies canonical loopback issuer port 9000 to it, preserving matching host and container issuer URLs.
- `ui/package-lock.json` dependencies were restored with `npm ci --offline --no-audit --no-fund` (55 packages; Playwright browser 1234 was already cached). The pinned OpenSpec package and lockfile are present under `tools/g0_ci/openspec`, but its `.bin/openspec` executable is absent; use the lockfile cache if available.
